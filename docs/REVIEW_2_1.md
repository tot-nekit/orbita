# Орбита 2.1 — решение по продукту и проверкам

22 октября 2026 года.

## Решение по продукту

Сохранить Орбиту как личный планировщик: быстро записать дело по-русски, увидеть всё незакрытое и получить напоминание в Telegram. Сайт и Mini App нужны для просмотра и исправления планов; Telegram — для быстрого ввода и уведомлений. Переписывать существующий стек ради этого не требуется.

Проведены три независимых агентских проверки: продукт/UX, бизнес-логика/хранилище, интерфейс/поставка. Основной агент объединил изменения и выполнил итоговые проверки. Один агент достиг лимита после внесения изменений; его код проверен основным агентом и автоматическими тестами.

## Что реализовано

- Разделы «Просрочено» и «Без даты», счётчики активных дел, корректные переходы после изменения и завершения. Демоимпорт скрыт под явным раскрытием.
- Парольный вход не возвращался. Удалены его HTML/JS/CSS и устаревшие инструкции; отвязка Telegram доступна только в связанном веб-пространстве.
- Даты вида «25 октября», часы словами, уточнение дня следующей недели, сохранение исходного названия встречи между репликами. Календарные слова в кавычках не назначают срок автоматически.
- Программная проверка явно распознанных дат и времени поверх результата LLM. Повторяющиеся запросы получают честное объяснение, несколько распознанных действий — предложение разделить сообщение.
- Проверка структуры ответа LLM, резервная модель и локальный режим при ошибках, ограничение ожидания, пауза после ограничения частоты. Интерфейс показывает фактический режим ответа.
- Сетевое планирование и STT вынесены за пределы SQLite-транзакций; снимок диалога проверяется перед применением. Повторы уже выполненных HTTP/Telegram запросов используют сохранённый результат.
- Подтверждение удаления связано с версией записи. Если запись успела измениться, требуется новое подтверждение.
- Устаревшие напоминания в очереди не отправляются спустя более часа; прежний worker не перезаписывает результат новой попытки после истечения аренды.
- Добавлена согласованная резервная копия SQLite с проверкой целостности (`python backup.py`). Перед обновлением локальная база сохранена отдельно.
- Архив пересобран без `.env`, токенов, базы, логов, виртуального окружения и `node_modules`. Секретные значения локальной конфигурации проверяются на отсутствие в исходниках архива.

## Выбор LLM

Используется официальный endpoint шлюза [VyceAI](https://vyceai.com/dashboard-v2): `https://vyceai.com/v1`.

| Роль | Настройка |
|---|---|
| Основная | `claude-sonnet-4-6` |
| Резервная | `deepseek-v4-flash` |
| Температура | `0.1` |
| Лимит ответа | `1200` токенов |
| Сетевой тайм-аут | `16` секунд на попытку |
| Речь через сервер | `STT_ENABLED=0` |

Это идентификаторы шлюза; фактическую модель за сторонним API независимо подтвердить нельзя. Рабочий ключ сохранён только в локальной конфигурации проекта. В архиве есть `.env.example`; на другом компьютере ключ нужно ввести локально.

Исходный сравнительный тест до исправлений — 10 одинаковых синтетических команд на модель:

| Модель шлюза | Успех | Среднее время |
|---|---:|---:|
| Claude Sonnet | 8/10 | 3,62 с |
| DeepSeek Flash | 6/10 | 1,08 с |
| GLM Flash | 6/10 | 2,86 с |
| GPT Luna | качество не оценено | HTTP 429 во всех попытках |

Claude выбран за точность исходных планов, DeepSeek — как быстрый резерв. Такой короткий тест не доказывает превосходство на любых запросах. GLM при исходном лимите 700 токенов дал четыре неразобранных JSON-ответа. Цены и фактическая стоимость не измерялись: требуется сверка биллинга аккаунта, а статический ценник интерфейса недостаточен.

## Итоговая проверка

- **172 Python unit/integration теста — PASS**, включая гонки напоминаний, устаревший диалог, повтор запроса и отсутствие write-lock во время планирования. В существующих тестах остаются ResourceWarning о закрытии тестовых объектов; они не скрывались и тесты не провалили.
- **WEB UI — PASS:** создание, изменение, поиск, удаление, отмена, валидация, четыре мобильных раздела, темы, inbox/overdue, состояния LLM/local/fallback, ошибки и недоступность STT. Нет JS pageerror.
- **MINI UI — PASS:** подписанные initData, блокировка анонимного Mini, создание, общие данные одного Telegram-владельца, изоляция аккаунтов, мобильные разделы, удаление. Telegram SDK эмулировался.
- **Реальный API + сервис + временная SQLite:** 8/8 сценариев для основной модели; 8/8 для резервной. Проверены напоминание, дедлайн, неделя, задача без даты, неподдерживаемое действие, отказ от повторения, продолжение уточнения и подтверждённое удаление. Отказ от повторения выполняет программа без запроса к модели.
- Локальное приложение перезапущено на `http://localhost:8000`; health и конфигурация версии 2.1 проверены, heartbeat Telegram-worker доступен.

Результаты: `orbita_model_benchmark.json`, `orbita_live_workflow.json` (итог основной модели), `orbita_live_workflow_fallback.json` (резервная модель).

## Следующий этап

1. Проверить настоящий Telegram на устройстве: запись → просмотр на сайте → перенос → фактическая доставка → завершение → перезапуск. В этой работе сообщения пользователю через Telegram специально не отправлялись. Эмуляция Mini и heartbeat не подтверждают получение уведомления.
2. Сделать уведомление свойством задачи/встречи: «в момент», «за 10 минут», «за час»; показать «отправлено/не доставлено/пропущено» и добавить отложить. Сейчас автоматическая доставка относится только к типу «напоминание».
3. Продумать сохранение и восстановление привязки пространства: при истечении Telegram-cookie сайт возвращается в общее `web`. Нужны понятное восстановление и подтверждаемый перенос локальных записей; молча объединять аккаунты нельзя.
4. Добавить простые повторения после проверки переноса и очереди доставки. Сейчас поддерживаются только одиночные события.
5. Подключать отдельный STT только после успешной проверки аудиофайла. У Vyce найденные документы подтверждают chat, но не transcription. Браузерный голосовой ввод доступен в поддерживаемом браузере.

Командные роли, биллинг, подзадачи, векторный поиск и двустороннюю синхронизацию календарей пока отложить. Сначала проверить недельное личное использование и реальную доставку.

Сайт остаётся без пароля и с общим веб-пространством, как было запрошено. Публикация такого сайта открывает это пространство всем посетителям; для личного локального использования он слушает `127.0.0.1`.
