# Архитектура Орбиты v2

## Каналы и общий домен

```text
Сайт (cookie) ───────┐
Mini App (Bearer) ───┼─ HTTP API ── service ── owner-scoped store ── SQLite WAL
Telegram Bot API ────┘                 │                             │
                              local parser / LLM             outbox + receipts
Telegram worker ── polling + scheduler ─────────────────────────────┘
```

UI — vanilla JavaScript/CSS без сборки и внешних шрифтов; Mini App использует официальный Telegram WebApp SDK. Сервер и bot-worker — отдельные Python-процессы; `run.py all` управляет обоими. Runtime требует Python 3.11+, на Windows — tzdata. Node/Playwright нужны только для UI-тестов.

## Модули

| Модуль | Ответственность |
| --- | --- |
| server.py | HTTP, авторизация, JSON API, cookie/Bearer, CSP, rate limits |
| security.py | Telegram HMAC, TTL initData, allowlist, подпись сессий, одноразовые коды |
| context.py | ContextVar текущего owner; owner не берётся из тела запроса |
| service.py | Валидация действий, уточнения, подтверждения, конфликты встреч |
| dates.py | Русские относительные даты и локальное время |
| ai.py | OpenAI-compatible LLM и STT через серверный API-ключ |
| store.py | SQLite, миграция v1, owner scope, CRUD, поиск, транзакции |
| telegram_bot.py | Long polling, команды/кнопки, voice confirmation, CSV |
| notifications.py | Durable outbox, lease, backoff, проверка актуальности |

## Авторизация и изоляция

Сайт без привязки использует пространство `web`. Все посетители без привязки используют одно общее веб-пространство. Telegram identity — `tg:<user_id>` после HMAC-проверки initData или доверенного update от Bot API. По умолчанию разрешены только ID из allowlist; публичный режим включается явно.

Сайт получает HttpOnly SameSite cookie, Mini App — Bearer в памяти. Сессии действуют 12 часов. Для Mini-запросов используется отдельный клиентский маркер: cookie сайта не должна подменять отсутствующий Telegram-вход. InitData старше часа, с дублирующимися полями, неверной подписью или недопустимым user ID отклоняется.

`/link` выдаёт одноразовый код на 10 минут; в SQLite сохраняется хеш. Его погашение атомарно переключает сайт на Telegram-пространство. Данные не объединяются и не удаляются. Все запросы к событиям, истории, настройкам и экспортам ограничены текущим owner.

## Сохранение и конкурентные изменения

SQLite работает в WAL; соединения закрываются после операций. `atomic()` использует BEGIN IMMEDIATE и общий connection в ContextVar для вложенных вызовов. Идемпотентная мутация и её receipt коммитятся одной транзакцией. Повтор ключа с тем же payload возвращает прежний ответ, с другим payload — конфликт. Receipt изолирован по owner, срок хранения 24 часа.

Редактирование проверяет revision, устаревшая форма получает 409. Пересечения встреч запрашивают явное подтверждение. Импорт уникален по `(owner, source_id)` и не перезаписывает уже отредактированную импортированную запись. Legacy-миграция сохраняет ID и переносит старые данные в web-пространство.

Удаление мягкое. Undo/восстановление доступны 10 минут; после этого данные остаются в SQLite, но скрыты из интерфейса. Физическая очистка пока не реализована.

## Диалог и AI

Локальный parser ограничен типовыми русскими запросами. LLM возвращает структурированный план, а не SQL. Сервер проверяет whitelist полей, типы, время, права и подтверждения; модель не может сама разрешить опасное действие через `_confirmed`. При нехватке деталей сохраняется pending state и задаётся вопрос. Голосовая расшифровка бота исполняется только после отдельного nonce-bound подтверждения.

Хранятся локальная дата, время и IANA timezone. Настройка нового пояса не пересчитывает старые события. Неоднозначные и несуществующие DST-времена отклоняются. Даты исходного CSV не сдвигаются к сегодняшнему дню.

## Доставка напоминаний

Один bot-worker опрашивает Telegram и каждые 15 секунд обрабатывает outbox. Напоминания импортированного датасета не доставляются. При первом обнаружении просрочки более часа запись помечается missed. Перед доставкой повторно проверяются owner, статус, срок, удаление и согласие на уведомления.

Сообщение захватывается lease на 90 секунд; до пяти попыток с backoff. Доставка at least once: сбой после принятия сообщения Telegram, но до локального sent, может дать повтор. Повторная доставка успешно отправленного события на тот же срок блокируется. Отключение и повторное включение доставки оживляет только отменённый, но не sent outbox.

## Границы прототипа

Стандартный HTTP-сервер, одна SQLite-база, один bot-worker. Горизонтальное масштабирование, полноценная SaaS-регистрация, Calendar sync, recurrence, browser push, векторный поиск и аудиоответы бота не реализованы. Существующий webhook не удаляется автоматически; long polling требует отсутствия webhook. Для внешнего доступа нужны HTTPS, стабильный секрет подписи, постоянный диск и always-on процесс. Доступ к общему веб-пространству следует ограничить на reverse proxy. Настройки Docker/Render приложены, но здесь не разворачивались.
