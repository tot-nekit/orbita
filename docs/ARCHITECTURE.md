# Архитектура Орбиты 3.1

## Каналы и общий домен

```text
Сайт (cookie) ───────┐
Mini App (Bearer) ───┼─ HTTP API ── service ── owner-scoped store ── SQLCipher WAL
Telegram webhook ───┘                 │                             │
                              local parser / LLM         inbox + outbox + receipts
Плановая задача ── повторы, напоминания, копии ─────────────────────┘
```

UI — vanilla JavaScript/CSS без сборки и внешних шрифтов; Mini App использует официальный Telegram WebApp SDK. На alwaysdata работает WSGI/Waitress website и scheduled task раз в минуту; постоянный polling не запускается. На собственном VPS `run.py all` управляет HTTP, Caddy, polling и копированием. Runtime требует Python 3.11+, на Windows — tzdata. Node/Playwright нужны только для UI-тестов.

## Авторизация и изоляция

Публичный сайт требует регистрации и использует личное пространство `u:<случайный ID>`. Почта не обязательна, пароли защищены scrypt. Без входа пользовательские API недоступны. Общее `web` существует только в явном локальном AUTH_REQUIRED=0; production этот режим отвергает. Telegram identity — `tg:<user_id>` после HMAC-проверки initData или доверенного update. Связанная Telegram identity разрешается в личный u:-аккаунт. По умолчанию разрешены только ID из allowlist; публичный режим включается явно.

Сайт получает случайный отзывной токен в HttpOnly SameSite cookie на 30 дней; база содержит его хеш. Production требует Secure. Выход, смена и восстановление пароля отзывают соответствующие сессии. Mini App получает отдельный Bearer на 12 часов в памяти. Cookie сайта не подменяет отсутствующий Telegram-вход. InitData старше часа, с дублирующимися полями, неверной подписью или недопустимым user ID отклоняется.

`/link` выдаёт одноразовый код на 10 минут; в базе сохраняется хеш. Подключение из личного аккаунта переносит принадлежащие этому Telegram записи и очередь в u:-пространство; чужая привязка отклоняется. Все запросы к событиям, истории, настройкам и экспортам ограничены текущим owner. Удаление аккаунта физически удаляет его записи, диалоги, токены и очередь; старые резервные копии живут до ротации.

## Сохранение и конкурентные изменения

SQLCipher 4 шифрует всю базу, WAL и online backup отдельным постоянным ключом. Это шифрование при хранении, не E2EE: сервер с ключом читает записи. Соединения закрываются после операций. `atomic()` использует BEGIN IMMEDIATE и общий connection в ContextVar для вложенных вызовов. Идемпотентная мутация и её receipt коммитятся одной транзакцией. Повтор ключа с тем же payload возвращает прежний ответ, с другим payload — конфликт. Receipt изолирован по owner, срок хранения 24 часа.

Редактирование проверяет revision, устаревшая форма получает 409. Пересечения встреч запрашивают явное подтверждение. Импорт уникален по `(owner, source_id)` и не перезаписывает уже отредактированную импортированную запись. Legacy-миграция сохраняет ID и переносит старые данные в web-пространство.

Удаление мягкое. Undo/восстановление доступны 10 минут; после этого данные остаются в SQLite, но скрыты из интерфейса. Физическая очистка пока не реализована.

## Диалог и AI

Локальный parser ограничен типовыми русскими запросами. LLM возвращает структурированный план, а не SQL. Сервер проверяет whitelist полей, типы, время, права и подтверждения; модель не может сама разрешить опасное действие через `_confirmed`. При нехватке деталей сохраняется pending state и задаётся вопрос. Голосовая расшифровка бота исполняется только после отдельного nonce-bound подтверждения.

Хранятся локальная дата, время и IANA timezone. Настройка нового пояса не пересчитывает старые события. Неоднозначные и несуществующие DST-времена отклоняются. Даты исходного CSV не сдвигаются к сегодняшнему дню.

## Доставка напоминаний

На alwaysdata webhook аутентифицируется отдельным секретом заголовка. Обновления сохраняются в зашифрованный inbox с уникальным ID и digest. Очередь ограничена 1000 ожидающими сообщениями и 20 на владельца; при переполнении возвращается 503 для повторной доставки Telegram. Конечная обработка запускается реальным входящим запросом, scheduled task восстанавливает прерванную работу. Порядок одного владельца сохраняется, lease на 300 секунд с токеном отсекает устаревший worker. После завершения исходный payload стирается.

Scheduled task проверяет напоминания раз в минуту; старт внутри минуты и сеть дают обычную задержку около 1–2 минут. На VPS polling-worker обрабатывает outbox раз в 15 секунд. Напоминания импортированного датасета не доставляются. При первом обнаружении просрочки более часа запись помечается missed. Перед доставкой повторно проверяются owner, статус, срок, удаление и согласие на уведомления.

Сообщение захватывается lease на 90 секунд; до пяти попыток с backoff. Доставка at least once: сбой после принятия сообщения Telegram, но до локального sent, может дать повтор. Повторная доставка успешно отправленного события на тот же срок блокируется. Отключение и повторное включение доставки оживляет только отменённый, но не sent outbox.

## Ограничения

Один website и одна база на постоянном диске. Горизонтальное масштабирование, Calendar sync, recurrence, browser push, совместные пространства и аудиоответы бота не реализованы. Polling и webhook одновременно не используются. Для внешнего доступа нужны HTTPS, регистрация, SQLCipher, постоянные ключи и рабочее расписание. Alwaysdata Free ограничен личным некоммерческим использованием, 256 МБ RAM, 1 ГБ диска и регулярным входом владельца в панель. Публичный запуск и реальная доставка на этом хостинге ещё не проверены.
