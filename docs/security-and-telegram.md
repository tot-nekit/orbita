# Защита и Telegram в 3.2

Приложение использует регистрацию, scrypt для паролей, отзываемые сессии, SQLCipher и резервные копии. Производственный режим требует HTTPS, постоянные ключи, шифрование базы и Secure cookies. Ключ базы нельзя заменять при обновлении — это закроет доступ к существующим данным.

## Профиль бота

Описание, команды, приветственное сообщение и аватар настраиваются без вывода токена: `python -m scripts.configure_telegram`. По умолчанию используется квадратный логотип `resources/orbita-bot.jpg`; его можно заменить через `TELEGRAM_BOT_PHOTO`.

## Подключение Telegram

1. Администратор задаёт `TELEGRAM_BOT_TOKEN`, проверенное имя `TELEGRAM_BOT_USERNAME`, постоянный `PUBLIC_BASE_URL` и список разрешённых `TELEGRAM_ALLOWED_USER_IDS`. Не публикуй эти настройки. Ровно один polling-worker должен работать с токеном бота.
2. В личном чате с ботом отправь `/start`, затем `/link`. Код действует десять минут и используется один раз.
3. Войди на сайт и открой Настройки → Telegram. Введи код и подтверди подключение своего Telegram.
4. В настройках появятся имя, `@username`, Telegram ID и состояние уведомлений. В боковой панели — «Telegram подключён». `/account` или `/status` в боте показывает связанный аккаунт.

Записи из отдельного Telegram-пространства переносятся в зарегистрированный аккаунт. После подключения сайт, бот и Mini App работают с одними данными. Если Telegram не входит в список доступа, бот покажет его ID; добавить ID может администратор. Пустой список не открывает публичный доступ сам по себе.

## Отключение

Настройки → Telegram → Отключить Telegram. Нужны текущий пароль и явное подтверждение. Записи остаются в аккаунте сайта, отправка уведомлений в Telegram прекращается. Старые токены, коды и ранее подписанные данные Mini App не восстанавливают прежний доступ. После повторной привязки Mini App нужно открыть заново. Выход с сайта сам по себе Telegram не отключает.

## Что ограничено

- Проверяются владелец каждой записи, точный Host, Origin и подпись Telegram. Произвольный owner из запроса игнорируется.
- Попытки входа, восстановления и подбора кодов ограничиваются в базе; лимиты сохраняются после перезапуска.
- Сессии и коды хранятся как хеши. Пароль, токен бота, ключ базы и API-ключи не отправляются браузеру.
- HTML-профиль Telegram отображается как текст; сторонние инструкции внутри названий записей не выполняются.
- Изменение и удаление учитывают версии записей. Telegram-подтверждения и голосовые черновики имеют срок действия.
- Waitress ограничивает число потоков, соединения, заголовки, тело запроса и время ожидания. Неверные JSON-объекты и неоднозначные ID отвергаются.
- Ограничиваются дневные обращения к внешнему ИИ. Если провайдер недоступен, остаются формы и локальные команды.

## Текущий сервер

Публичный адрес — `https://213.171.29.94/`. Nginx обслуживает IP-сертификат Let's Encrypt и проксирует на локальный порт Docker. Входящий 8000 не публикуется в интернет. Нужны TCP 80 для проверки продления и TCP 443 для сайта. Автопродление проверяется дважды в сутки; короткий срок IP-сертификата требует работающего `orbita-cert-renew.timer`.

На Nginx установлены лимиты запросов, соединений и попыток авторизации. SSH защищён fail2ban. Обновления безопасности Ubuntu включены без автоматической перезагрузки ВМ. Приложение работает непривилегированным пользователем. Зашифрованная резервная копия перед обновлением сохранена отдельно от ВМ.

## Проверки и пределы

`python -m scripts.test` выполняет изолированные серверные тесты без настоящих ключей и пользовательской базы. `npm run test:ui` проверяет браузерные сценарии. Тесты включают разделение аккаунтов, отзыв сессий, привязку/отвязку, старые подписи и кнопки, восстановление данных и ошибки транспорта.

Эти меры не означают неуязвимость и не заменяют защиту от масштабной DDoS-атаки у провайдера. Сервер с ключом может расшифровать базу; это не сквозное шифрование. Нужны защищённый доступ к Cloud.ru, резервные копии и своевременное обновление контейнеров. Секреты, ранее переданные в переписке, следует заменить вручную с сохранением ключа существующей базы. Реальную доставку в Telegram проверяй на своём аккаунте, отдельно от тестов с эмуляцией API.
