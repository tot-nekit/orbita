# Подключить Telegram-бота и Mini App

## 1. Создай своего бота

В официальном Telegram-боте **@BotFather** используй `/newbot`, задай имя и свободный username. Сохрани выданный токен приватно. Не отправляй его в чат, не вставляй в репозиторий и скриншоты.

В своём локальном терминале запусти `python -m scripts.configure` или заполни `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=твой_токен
TELEGRAM_BOT_USERNAME=твой_username_без_собаки
TELEGRAM_ALLOWED_USER_IDS=
TELEGRAM_ALLOW_PUBLIC=0
```

## 2. Разреши доступ себе

1. Запусти `python run.py bot`.
2. Открой бота и отправь `/id`. Даже при закрытом доступе он вернёт **твой собственный** числовой Telegram ID, но не данные аккаунта.
3. Добавь ID в `TELEGRAM_ALLOWED_USER_IDS`, останови и перезапусти worker.
4. Отправь `/start`.

Можно перечислить несколько ID через запятую. Без списка бот по умолчанию закрыт. `TELEGRAM_ALLOW_PUBLIC=1` открывает бота всем и может расходовать твой API-бюджет. Если список непустой, именно он ограничивает доступ даже при public=1.

## 3. Проверь бота без Mini App

Входящий HTTPS для long polling не нужен — достаточно исходящего доступа к api.telegram.org:

- «Добавь задачу купить билеты».
- «Поставь встречу завтра» → ответь временем.
- `/today`, `/tomorrow`, `/week`.
- `/find презентация`.
- `/export` → CSV-документ.
- `/timezone Europe/Moscow`.
- `/notify on` или `/notify off`.
- `/cancel` — отмена незавершённого действия.

Голосовые требуют ключа и доступного STT endpoint. Поддержка STT у Vyce не подтверждена; наличие работающей LLM не подтверждает распознавание голоса. В UI доступность серверного распознавания задаёт `stt` из `/api/config`. Расшифровка сначала показывается пользователю, действие выполняется кнопкой «Выполнить». Старая кнопка не должна выполнять новую расшифровку: к ней привязан nonce.

Бот работает только в личных чатах. Группы и inline mode не обслуживаются.

## 4. Опубликуй Mini App

1. Разверни сайт с валидным HTTPS-сертификатом и постоянным диском.
2. Задай `PUBLIC_BASE_URL=https://твой-домен` **без `/mini`**.
3. Задай `COOKIE_SECURE=1`, случайный APP_SESSION_SECRET и ограничение доступа к общему веб-пространству на reverse proxy.
4. Перезапусти `python run.py all`.

Worker выставит команды и кнопку меню через Bot API. В приветствии появится «Открыть планировщик». Кнопка открывает `https://твой-домен/mini`.

Если webhook уже настроен другой системой, worker остановится с объяснением. Нужно **осознанно** удалить прежний webhook через Bot API `deleteWebhook` или использовать отдельного бота. Приложение не удаляет его и не выбрасывает pending updates автоматически.

Не запускай два long-polling процесса одного бота одновременно. В настройках хостинга держи один экземпляр приложения с одним worker, без auto-scale.

## 5. Привяжи веб-сайт

- В боте `/link` → код 10 символов, срок 10 минут.
- На сайте открой Настройки → Telegram → введи код и подтверди. Кнопка «Отвязать Telegram от сайта» возвращает к общим веб-записям и видна только связанному веб-аккаунту; в Mini App она скрыта.
- После обновления сайт использует тот же owner, что бот и Mini App.

Старое веб-пространство не объединяется и не удаляется. Переключение обратно: «Выйти / отключить привязку сайта» и обычный вход на сайт. Это намеренная защита от незаметного смешивания баз.

## 6. Проверь реальное напоминание

После `/start` и `/notify on` создай «Напомни через две минуты проверить прототип». Оставь worker работающим. Ожидай сообщение в личном чате с кнопкой завершения. При отправке с сайта убедись, что он уже связан с Telegram.

Если сервер не работал более часа после срока, впервые обнаруженное старое напоминание помечается missed и не рассылается. Уже поставленные сообщения пробуются до 5 раз. Для реального сервиса нужна постоянно работающая инфраструктура; это не гарантированная служба экстренных уведомлений.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Бот пишет «Доступ ограничен» | /id → allowlist → перезапуск |
| Бот молчит, в журнале «Telegram API unreachable» | сервер не видит api.telegram.org — задай `TELEGRAM_PROXY` |
| В журнале «Another bot instance uses this token» | где-то запущен второй бот с тем же токеном (например, локально) — останови его |
| Mini App не открывается | PUBLIC_BASE_URL, HTTPS, меню после перезапуска |
| `/mini` в браузере закрыт | Это правильно: открой кнопкой Telegram |
| Сессия истекла | Закрой Mini App и открой снова из бота |
| Подпись не прошла проверку | Один и тот же bot token у сайта и worker; актуальные часы сервера |
| Разные записи на сайте и в боте | Связан ли сайт через /link; не другой ли Telegram-пользователь |
| Нет уведомлений | /start, notify=on, kind=reminder, срок, worker, сеть, блокировка бота |
| Голос не распознаётся | API-ключ, баланс/доступ к STT, размер/длительность |
| Экспорт не скачивается в WebView | /export в боте; в Mini App экспорт переводит в бот при заданном username |
| После redeploy всё исчезло | Постоянный диск /app/data и права UID 10001 |

## Технические источники

Telegram описывает передачу `initData`, необходимость серверной проверки и WebApp API в официальной документации: https://core.telegram.org/bots/webapps. Bot API: https://core.telegram.org/bots/api.

В проекте нельзя подменять серверную HMAC-проверку чтением `initDataUnsafe`. UI-тест с эмуляцией SDK — не подтверждение работы конкретной версии Telegram/iOS/Android.
