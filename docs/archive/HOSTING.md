# Эксплуатация

Для выбранного бесплатного shared hosting см. [ALWAYSDATA.md](ALWAYSDATA.md): сайт, webhook и scheduled task. Описанные ниже Caddy, Docker и постоянные workers относятся к собственному VPS.

Один экземпляр: внешний HTTPS proxy → Caddy контейнера → Python на loopback. В том же контейнере работают Telegram polling (если настроен) и резервное копирование. Горизонтальное масштабирование SQLite и два polling-процесса на один токен не поддерживаются.

## Запуск и остановка

`docker compose up --build -d` создаёт локальный контейнер с постоянным томом, без заказа платных услуг. Новый хостинг в этой поставке не создаётся. Нужен существующий сервер или подходящий бесплатный VPS; см. [DEPLOYMENT.md](DEPLOYMENT.md).

Launcher запускает дочерние процессы в отдельных группах. Неожиданный выход любого worker останавливает службу с кодом ошибки для перезапуска Docker/systemd. SIGTERM/SIGINT останавливают все группы, общий срок — 10 секунд. Проверка HTTP начинается через 60 секунд; три неудачи с интервалом 30 секунд также завершают службу для перезапуска.

Docker получает restart: unless-stopped. Healthcheck сам по себе не перезапускает unhealthy-контейнер; это делает supervisor при повторных ошибках. На хосте должен быть включён автозапуск Docker. Не используй compose down -v для обновления.

## Обязательные настройки production

| Переменная | Значение |
| --- | --- |
| APP_ENV | production |
| PUBLIC_BASE_URL | Точный HTTPS origin без пути, query, логина и пароля |
| HOST | 127.0.0.1 |
| PORT / APP_PORT | 8000 / 8001, разные порты |
| AUTH_REQUIRED / DATABASE_ENCRYPTION / COOKIE_SECURE | 1 / 1 / 1 |
| DATABASE_PATH | /app/data/orbita.sqlite3 на постоянном томе |
| DATABASE_KEY | Постоянные 32 случайных байта в base64url |
| APP_SESSION_SECRET | Другой постоянный случайный секрет, минимум 32 символа |

Ключи находятся в секретах сервера, не в Git. DATABASE_KEY_FILE подходит для приватного файла на хосте; Compose ожидает DATABASE_KEY из секретного окружения. Сохрани ключ отдельно от диска базы. Замена переменной не выполняет ротацию существующей базы.

Без AI/Telegram-ключей соответствующие интеграции выключены. Внешний AI может тарифицироваться независимо от VPS. Дневные лимиты задаются AI_DAILY_USER_LIMIT и AI_DAILY_LIMIT; новые аккаунты не разрешают отправку текста до явного включения.

## HTTP и сборка

Образ Python 3.13 использует закреплённый wheel sqlcipher3 0.6.4 с SQLCipher 4 и отдельный бинарный Caddy 2.10.2. Поддерживаются Linux amd64/arm64. Компилятор не нужен. Данные, .env, ключи, архивы и Git исключены из Docker build context; процесс работает под UID 10001.

HTTPS завершает внешний proxy. Контейнер публикует HTTP только на 127.0.0.1:8000, внутренний Python слушает 127.0.0.1:8001. Внешний proxy сохраняет Host и корректно перезаписывает X-Forwarded-For. Встроенный Caddy доверяет forwarded IP только от частных proxy-адресов и передаёт собственный X-Orbita-Client-IP, удаляя входящие forwarded-заголовки к Python.

Caddy ограничивает тело 16 МБ, заголовки 32 КБ, соединения с backend — 16. Таймауты: чтение заголовка 10 с, тела 30 с, запись ответа 90 с, idle 30 с; соединение с backend 3 с, ожидание ответа 75 с. Request access log не включён. Собственный внешний proxy и провайдер могут вести журналы отдельно.

Анонимный /api/health выполняет реальное чтение базы. Страница /api/config требует входа. Production сверяет Host с PUBLIC_BASE_URL; health имеет исключение для локальных проверок. Наличие ответа health не доказывает реальную доставку Telegram и доступность LLM.

## Резервные копии

BACKUP_ENABLED=1 включает worker. Первая копия создаётся при запуске, затем каждые BACKUP_INTERVAL_HOURS (по умолчанию 6). BACKUP_KEEP=28 хранит около недели при непрерывном расписании. Неверные значения заменяются безопасными значениями без вывода содержимого настройки.

`backup.create_backup(output=None)` использует online backup API, включает зафиксированные WAL-изменения, шифрует тем же ключом и проверяет целостность. Копия повторно открывается перед атомарной публикацией; существующие пути и symlink не перезаписываются. На POSIX права 0600. Частичная неудачная копия удаляется.

```sh
python backup.py --output /safe/new-snapshot.sqlite3
```

Автокопии находятся в data/backups. Ротация удаляет только обычные файлы с точным шаблоном orbita-auto-*.sqlite3 после создания новой успешной копии. Ручные файлы, symlink и директории не участвуют.

Копии на том же диске не защищают от его потери. Нужна отдельная защищённая внешняя копия и мониторинг свободного места. Ключ хранится отдельно. Никакой внешний storage или платный backup-сервис не создаётся автоматически.

Восстановление сначала проверяется на отдельном пути правильным ключом, integrity_check и сверкой записей. Все workers останавливаются перед заменой рабочей базы; прежняя версия сохраняется для отката. См. [PRIVACY.md](PRIVACY.md).

## Доступность

Один сервер, диск и регион могут отказать. Бесплатный Oracle может отозвать простаивающий экземпляр; сна бесплатного веб-тарифа здесь нет, но гарантия непрерывного uptime не заявляется. Внешний монитор должен проверять HTTPS health и сообщать владельцу о сбое. Для подтверждения публикации нужны живые проверки регистрации, двух аккаунтов, перезапуска и восстановления; зелёные офлайн-тесты не заменяют их.
