# Исправление запуска v2.0.1

Причина: сайт и bot-worker одновременно переключали SQLite в WAL и инициализировали схему.

Изменено:
- launcher завершает инициализацию базы до запуска дочерних процессов;
- переход в WAL повторяется при SQLITE_BUSY/locked, соединение закрывается и при ошибке;
- миграция схемы сериализована BEGIN IMMEDIATE без implicit commit executescript.

Проверено на Linux/Python 3.13: 142 unit/integration теста PASS; 8 отдельных процессов одновременно открывают новую базу, затем отдельный сценарий из 8 процессов мигрирует legacy-базу с сохранением записи. Дополнительно проверены retry и закрытие соединения при ошибке. macOS/Python 3.14 на устройстве пользователя здесь не проверялись.

Остановить приложение. Распаковать содержимое архива в существующую папку orbita с заменой app/store.py и run.py. Перед обновлением проверь, что новая сборка не содержит .env, секрета подписи и рабочей базы; сохраняй свою конфигурацию и данные. Этот документ не подтверждает состав старых архивов. Повторная настройка configure.py не нужна.

Запуск: source .venv/bin/activate && python run.py all
