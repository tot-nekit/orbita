# Бесплатная публикация на alwaysdata

Выбранный профиль для небольшого личного проекта без VPS. Условия проверены 26 октября 2026: Free — 0 €/месяц без срока окончания, 1 ГБ общего диска, 256 МБ RAM, ¼ CPU, адрес account.alwaysdata.net с HTTPS, резервные копии провайдера за 3 дня. Это ограниченный общий хостинг, не гарантия непрерывного uptime.

## Условия, от которых зависит доступность

- Только личное некоммерческое использование. Для бизнеса, рекламы, продаж и собственного домена Free не подходит.
- Заходи в панель управления хотя бы раз в 120 дней. В первый год аккаунт приостанавливается без такого входа; посещения сайта этого не заменяют. У более старых аккаунтов интервал больше.
- Постоянные фоновые services на Free запрещены. Сайт работает как website; Telegram получает настоящие входящие webhook-запросы. Напоминания, повторные попытки и копии выполняет разрешённая scheduled task. Никакого искусственного трафика для удержания процесса.
- По умолчанию AI и Telegram выключены. Внешний LLM тарифицируется провайдером отдельно. Без него работают формы и локальные команды.

## Первая установка

Создай аккаунт Free на [странице регистрации](https://www.alwaysdata.com/en/register/?p=2012), подтверди почту и выбери имя аккаунта. Пароль и согласие на условия вводит владелец лично. Карта и платное повышение тарифа для этой конфигурации не нужны.

В панели выбери Python 3.13. Загрузи чистый архив исходников в /home/ACCOUNT/orbita или клонируй приватный репозиторий через отдельный SSH deploy key только на чтение. Не загружай node_modules, локальную .venv, старую .env или пользовательскую базу из релиза: они не входят в архив.

В SSH-терминале хостинга, из папки проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir --only-binary=sqlcipher3 -r requirements.txt
.venv/bin/python prepare_hosted.py --url https://ACCOUNT.alwaysdata.net
```

Замени ACCOUNT на имя аккаунта. Скрипт создаёт .env и отдельный ключ с правами 0600, базу размещает в ~/orbita-private/. Существующие файлы не перезаписывает. При обновлении этот скрипт повторно не запускается. Храни защищённую копию ключа вне хостинга: без него данные и резервные копии не открыть.

## Website

В Web > Sites создай сайт:

| Поле | Значение |
| --- | --- |
| Address | ACCOUNT.alwaysdata.net |
| Type | User program |
| Command | /home/ACCOUNT/orbita/.venv/bin/python /home/ACCOUNT/orbita/hosted.py |
| Working directory | /home/ACCOUNT/orbita |
| HTTPS | Включён, HTTP перенаправляется на HTTPS |

Платформа передаёт IP и PORT. Не фиксируй их в .env. Waitress использует именно эти значения, а не отдельный Caddy. Один сайт, 4 потока, до 16 соединений, тело запроса до 2 МБ. Частное аудио не сбрасывается во временные открытые файлы. Нет Docker, run.py all, polling-worker и сервиса резервного копирования.

Проверь, что HTTP действительно перенаправляется на HTTPS, сертификат действителен и /api/health отвечает. Затем создай два тестовых аккаунта, проверь изоляцию и сохранность записей после перезапуска website.

Платформа перезаписывает X-Real-IP. В TRUSTED_PROXY_CIDRS укажи только проверенные адреса/CIDR её непосредственного proxy, полученные из фактического окружения или поддержки. Пустое значение безопасно: используется адрес соединения, но ограничения попыток входа могут быть общими для посетителей за одним proxy. Не ставь 0.0.0.0/0 и не доверяй заголовкам произвольного клиента. До публичного открытия проверь подмену X-Real-IP извне.

## Scheduled task

В Advanced > Scheduled tasks добавь команду каждую минуту:

```sh
/home/ACCOUNT/orbita/.venv/bin/python /home/ACCOUNT/orbita/scheduled.py
```

Она проверяет очередь Telegram, доставляет напоминания и создаёт проверенную зашифрованную копию, если с предыдущей прошло 6 часов. Платформа не запускает тот же task повторно, пока предыдущий не завершился. Задача запускается внутри назначенной минуты: обычная задержка напоминания составляет около 1–2 минут, при сбоях дольше. Интерфейс показывает доступность планировщика по heartbeat. Это не сервис точной доставки по секундам.

Копии находятся в ~/orbita-private/backups/, хранятся 28 последних. Резервные копии на том же аккаунте не заменяют внешнюю защищённую копию. Следи за квотой 1 ГБ: в неё входят зависимости Python, база, журналы, почта и копии. При росте данных сначала выгрузи копии; не удаляй действующий ключ или базу.

## Telegram и AI

В приватной .env на сервере задай токен бота, username и разрешённые ID. TELEGRAM_MODE остаётся webhook. Для открытого бота отдельно включи TELEGRAM_ALLOW_PUBLIC=1. Секрет webhook уже создан, не используй вместо него токен BotFather.

Перед переключением останови прежний локальный polling-процесс того же бота. Убедись, что публичный HTTPS работает, затем выполни:

```sh
.venv/bin/python setup_webhook.py
```

Команда не сбрасывает ожидающие сообщения, проверяет адрес webhook и настраивает Mini App. Проверь /start, привязку к личному аккаунту, создание записи и доставку нового напоминания. Подтверждение webhook не доказывает, что scheduled task работает: проверь её успешные запуски в панели.

Входящие обновления сначала сохраняются в зашифрованную очередь. Повтор Telegram не создаёт вторую запись. После прерывания обработка возобновляется; занятое сообщение освобождается через 5 минут. Исходный текст завершённых заданий стирается, служебные ID сохраняются до 7 дней. Редкий повтор исходящего сообщения возможен при неоднозначном сетевом ответе Telegram.

API-ключ AI при необходимости добавляется только в секретную .env, не в GitHub и не в архив. Новые аккаунты отдельно разрешают AI в настройках. Нулевой бюджет хостинга не означает бесплатные запросы к VyceAI.

## Обновления и проверка

Сначала копия базы и отдельно ключа. Обнови исходники без замены .env, ~/orbita-private/ и ключа; установи зависимости, перезапусти website через панель. Расписание и его пути сохраняются. Проверки: HTTPS health, регистрация, вход, две изолированные учётные записи, запись после перезапуска, свежая копия и успешные scheduled task. Эксперимент восстановления выполняется на отдельном пути.

Публичная публикация этой версии пока не выполнена. Локальные тесты проверяют WSGI, шифрование, перезапуск и webhook с подменённым Telegram; фактические лимиты аккаунта и доставка проверяются после создания хостинга.
