# LLM и VyceAI: проверенная конфигурация

Проверка выполнена 22 октября 2026 года. Официальная страница шлюза: https://vyceai.com/dashboard-v2. В её примерах указан OpenAI-compatible endpoint `https://vyceai.com/v1`; авторизованный `/v1/models` подтвердил доступные идентификаторы. Маркетинговое название и поле `model` шлюза не позволяют независимо установить, какая модель исполняет запрос на стороне провайдера.

## Решение

Основная модель — `claude-sonnet-4-6`, резервная — `deepseek-v4-flash`. Для данного планировщика точность важнее небольшой разницы в задержке. Не требуется дорогая модель с большим контекстом: отправляются запрос и короткое состояние диалога, а не вся база.

```dotenv
OPENAI_BASE_URL=https://vyceai.com/v1
OPENAI_MODEL=claude-sonnet-4-6
LLM_FALLBACK_MODEL=deepseek-v4-flash
LLM_TEMPERATURE=0.1
LLM_MAX_TOKENS=1200
LLM_TIMEOUT=16
STT_ENABLED=0
```

Ключ вводится локально через `python configure.py` или в `.env` как `OPENAI_API_KEY`. В архиве рабочего `.env` нет. Не переносите ключ в браузерный JS.

## Что показало сравнение

Исходный prompt, одинаковые 10 синтетических русских команд на каждую модель, до добавления календарных подсказок и дополнительных ограничений:

| ID шлюза | Пройдено | Средняя задержка | Наблюдение |
|---|---:|---:|---|
| claude-sonnet-4-6 | 8/10 | 3,62 с | Ошибки дедлайна и повторения |
| deepseek-v4-flash | 6/10 | 1,08 с | Ошибки дат, недели и повторения |
| glm-5.3-flash | 6/10 | 2,86 с | 4 неразобранных JSON-ответа при исходном лимите 700 токенов |
| gpt-6-luna | нет оценки | — | 10 ответов HTTP 429; это ограничение доступности, не оценка качества |

Это небольшой smoke benchmark, не универсальный рейтинг. В проверке уточняющего вопроса оценивалось действие `clarify`, а не каждое слово ответа: у Claude встречалась неверная дата внутри вопроса, несмотря на правильный тип действия. Цены не измерялись: `/models` не возвращает полный биллинг, а статические значения интерфейса не заменяют тариф аккаунта.

После исправлений проведены отдельные проверки реального API вместе с SQLite и сервисом на временной базе. Сырые результаты поставляются рядом с архивом как JSON. Не следует смешивать этот итог с исходной оценкой моделей.

## Контракт приложения

- Программа вычисляет распознанные даты, время и границы недели; они приоритетнее арифметики модели. Календарные слова внутри кавычек не меняют срок записи.
- LLM только предлагает действие. JSON, типы, даты, длительность и поля проверяются до применения; неизвестные поля не исполняются.
- Повторения пока не поддерживаются. Такой запрос получает честное уточнение, а не разовое напоминание.
- Широкий срок создания сохраняется в незавершённом действии. Ответ «в пятницу в 12» продолжает исходную встречу.
- При ошибке основного API выполняется попытка резервной модели, затем локальный разбор с видимым уведомлением. Для HTTP 429 действует пауза 60 секунд, для прочих ошибок — короткая пауза; это не гарантирует восстановление внешнего сервиса.
- Тайм-аут 16 секунд задаётся на сетевую попытку, а не как жёсткий общий deadline. Две модели могут потребовать примерно 32 секунды; DNS и транспорт могут добавить задержку.
- Запросы к LLM и распознаванию речи вынесены из транзакции записи. Результат применяется в короткой транзакции с проверкой снимка диалога; изменившийся диалог требует повторного запроса.
- Повтор HTTP-запроса с тем же ключом и Telegram update с тем же ID возвращают сохранённый результат без повторной мутации.

## Голос

Совместимость `/chat/completions` не означает поддержку `/audio/transcriptions`. Последний endpoint не указан в найденном списке возможностей VyceAI, поэтому серверное STT отключено. Доступен голосовой ввод поддерживаемого браузера. Для другого провайдера речи задайте `STT_ENABLED=1`, `STT_BASE_URL`, `STT_API_KEY` и `STT_MODEL`; отдельно проверьте реальный аудиофайл. Текстовый ввод не зависит от STT.

## Резервное копирование

`python backup.py` делает согласованную SQLite-копию в `data/backups/` и проверяет `integrity_check`. Можно указать новый путь через `--output`. Для восстановления остановите приложение, сохраните отдельно текущую базу и её WAL/SHM при наличии, затем разместите проверенную копию по `DATABASE_PATH` и запустите приложение. Сначала проверяйте восстановление на отдельной временной базе. Ключи `.env` в копию SQLite не входят; история и личные записи входят.
